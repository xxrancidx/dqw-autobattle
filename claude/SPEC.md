# DQW 自動戦闘システム — 要件定義書

**プロジェクト名:** DQW AutoBattle System  
**作成日:** 2026-04-09  
**ステータス:** Draft v1.0

---

## 1. プロジェクト概要

scrcpy を利用して PC にミラーリングした Android スマートフォン上の「ドラゴンクエストウォーク」を、画像認識と ADB コマンドにより自動操作し、戦闘を自動的に遂行するシステム。

### 1.1 目的

フィールド上の敵シンボルの自動タップ、および Walk モード（半自動戦闘モード）のオンオフ切り替えを自動化し、プレイヤーの操作負担を軽減する。

### 1.2 注意事項

本システムの使用はドラゴンクエストウォークの利用規約に抵触する可能性がある。アカウント停止（BAN）等のリスクを理解した上で、自己責任での運用を前提とする。

---

## 2. スコープ

### 2.1 MVP（初期リリース）スコープ

| 機能 | 説明 |
|------|------|
| Walk モード切り替え | Walk モードのオン/オフボタンを画像認識し自動タップ |
| 敵シンボルタップ | フィールド画面上の敵シンボルを認識しタップ |
| シンボル探索 | 敵シンボルが認識できない場合、画面を2秒間スクロール→停止→再探索を繰り返す |
| ダイアログ自動処理 | 想定外のポップアップ（通信エラー、イベント通知等）を検知し、OK/閉じるボタンをタップして復帰を試みる |
| エラーハンドリング | ダイアログ復帰を3回リトライ後、状態が回復しない場合はシステムを停止しダッシュボードに通知 |
| ダッシュボード | Web ベースの監視 UI（状態表示、ログ表示、開始/停止制御） |

### 2.2 スコープ外（将来検討）

- 戦闘コマンドの手動選択（スキル・呪文の選択制御）
- 自動徒歩移動（GPS 連携）
- 回復・装備管理の自動化
- 複数端末の同時制御

## 3. システム構成

### 3.1 全体アーキテクチャ

```
[Android: Pixel 8] --USB--> [PC: Windows]
                               |
                      scrcpy (ミラーリング)
                               |
              +----------------+----------------+
              |                |                |
        画面キャプチャ層   状態認識層      操作実行層
              |                |                |
              +--------+------+-------+--------+
                       |              |
                  ステートマシン   ダッシュボード
                  (メインループ)   (Web UI)
```

### 3.2 コンポーネント詳細

#### 3.2.1 画面キャプチャ層

- **方式:** `adb exec-out screencap -p` によるスクリーンショット取得
- **代替:** scrcpy ウィンドウのキャプチャ（mss / pyautogui）
- **取得間隔:** 500ms〜1000ms（状態に応じて可変）
- **対象解像度:** Pixel 8 — 1080 x 2400（FHD+）

#### 3.2.2 状態認識層

- **主要技術:** OpenCV テンプレートマッチング
- **認識対象:**
  - Walk モードボタン（ON 状態 / OFF 状態）
  - 敵シンボル（フィールド上のモンスターアイコン）
  - ダイアログ（OK ボタン、閉じるボタン）
  - 戦闘中画面（戦闘開始〜終了の判定）
  - リザルト画面
- **テンプレート画像:** 事前にスクリーンショットから切り出して `/templates/` に格納
- **マッチング閾値:** 0.8（調整可能な設定値として外部化）

#### 3.2.3 操作実行層

- **方式:** `adb shell input tap <x> <y>` によるタップ送信
- **スワイプ:** `adb shell input swipe <x1> <y1> <x2> <y2> <duration_ms>`
- **操作間隔:** 最低 300ms のクールダウン（誤タップ防止）
- **座標方式:** Pixel 8 固定座標（将来的に相対座標方式へ移行）

#### 3.2.4 ステートマシン（メインループ）

システムの中核。有限オートマトンとして以下の状態を遷移する。

**状態一覧:**

| 状態 | 説明 | 遷移先 |
|------|------|--------|
| `IDLE` | システム待機中 | → `SEARCHING` |
| `SEARCHING` | フィールド上で敵シンボルを探索中 | → `SCROLLING` / `TAPPING_ENEMY` |
| `SCROLLING` | シンボル未発見時のスクロール中（2秒） | → `SEARCHING` |
| `TAPPING_ENEMY` | 敵シンボルをタップ | → `IN_BATTLE` / `SEARCHING` |
| `IN_BATTLE` | 戦闘中（Walk モード動作中） | → `BATTLE_RESULT` |
| `BATTLE_RESULT` | リザルト画面の処理 | → `SEARCHING` |
| `DIALOG_HANDLING` | 想定外ダイアログの処理中 | → (復帰前の状態) / `ERROR` |
| `ERROR` | 復帰不能エラー（システム停止） | → `IDLE`（手動再開） |

#### 3.2.5 ダッシュボード（Web UI）

- **技術:** FastAPI（バックエンド）+ HTML/JS（フロントエンド）
- **ポート:** `http://localhost:8080`
- **表示内容:**
  - 現在のステートマシン状態
  - 直近のキャプチャ画像プレビュー
  - リアルタイムログストリーム（WebSocket）
  - 戦闘回数カウンター
  - エラー発生回数
  - 稼働時間
- **操作:**
  - 開始 / 停止ボタン
  - Walk モード強制切り替え
  - 設定値の動的変更（マッチング閾値、スクロール時間等）

## 5. ログ・記録仕様

デバッグおよび運用監視のため、以下の情報を記録する。

### 5.1 ログレベルと出力先

| レベル | 出力先 | 用途 |
|--------|--------|------|
| DEBUG | ファイル | 全状態遷移、認識結果の詳細スコア |
| INFO | ファイル + ダッシュボード | 主要イベント（戦闘開始、終了、エラー復帰） |
| WARNING | ファイル + ダッシュボード | 認識失敗、リトライ発生 |
| ERROR | ファイル + ダッシュボード + 通知 | 復帰不能エラー |

### 5.2 記録項目

- **状態遷移ログ:** タイムスタンプ、遷移元状態、遷移先状態、トリガー
- **画像認識ログ:** テンプレート名、マッチングスコア、検出座標、判定結果
- **操作ログ:** 実行コマンド（tap/swipe）、座標、実行結果
- **スクリーンショット保存:** エラー発生時、状態遷移失敗時に自動保存（`/logs/screenshots/`）
- **統計情報:** 戦闘回数、エラー回数、平均戦闘時間、稼働時間

### 5.3 ログローテーション

- ファイルサイズ: 10MB でローテーション
- 保持世代数: 5世代
- スクリーンショット: 直近100枚を保持（古いものから自動削除）

## 9. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| 利用規約違反によるBAN | アカウント喪失 | 操作間隔にランダム性を持たせる、長時間連続稼働を避ける |
| アプリ UI 更新によるテンプレート不一致 | 認識失敗 | テンプレート画像を差し替え可能な設計、マッチング閾値の外部設定化 |
| ADB 接続切断 | システム停止 | 接続監視と自動再接続ロジック |
| 端末の発熱・バッテリー劣化 | 端末故障 | 1時間以内の稼働制限、温度監視（将来） |
